# Boss 直聘招聘省 Token 工作流

更新时间：2026-06-09

## 1. 目标

减少在 Boss 直聘上反复读取长聊天、长简历、长岗位说明造成的 token 消耗，同时保留判断质量。

核心原则：

- 长材料只读一次，沉淀成短摘要。
- 稳定规则写入本地文档，不在每轮对话重复展开。
- 候选人沟通使用模板 + 少量个性化变量。
- 批量处理时只保留候选人关键字段、风险点、下一步动作。

## 2. Skill、知识库、报告的区别

### Skill

Skill 是“可复用工作流”。适合放流程、判断顺序、模板、脚本入口。

适合写入 Skill 的内容：

- Boss 直聘招聘操作流程。
- 求简历、读附件、做小任务、判断候选人的步骤。
- 标准话术模板。
- 何时停止追问、何时推进面谈。

### 知识库

知识库是“长期事实和偏好”。适合放稳定背景信息。

适合写入知识库的内容：

- 律所地址、岗位卖点、作息制度。
- 用户偏好：可塑性 > 现成专业性。
- 本地成本优势、AI 协作办案训练。
- 团队履历、设备配置、AI 工具链、办公氛围、公众号/抖音入口。
- 候选人评估口径。
- 薪资边界：普通文员/律师助理不提前承诺具体数字；超出岗位预算的薪资通常要对应授薪律师、律师证、可出庭/会见或明显独立办案价值。

### 报告

报告是“阶段性复盘”。适合放当前批次候选人、判断、结果和教训。

适合写入报告的内容：

- 候选人名单。
- 每人的简历摘要、小任务表现、沟通进展。
- 哪类话术有效，哪类无效。
- 下一步待办。

## 3. 推荐上下文结构

每次继续招聘前，只加载四类短信息：

1. 岗位固定信息：律所地点、作息、社保、AI 训练卖点。
2. 筛选规则：地点接受、简历、小任务、沟通质量。
3. 当前候选人表：每人 5-8 行摘要。
4. 当前待办：谁要回复、谁要约面、谁要发任务。

避免加载：

- 全量 Boss 聊天记录。
- 已经总结过的 PDF/docx 全文。
- 反复复制岗位介绍。
- 反复解释 AI 协作理念。

## 4. 候选人摘要格式

后续每个候选人只保留这种短格式：

```text
姓名：
岗位：
地点/期望：
学历/专业：
学校层级内部判断：
关键经历：
简历亮点：
风险点：
小任务表现：
当前状态：
下一步：
```

说明：

- “学校层级内部判断”只用于内部校准，不进入对外话术。
- 如果候选人小任务完成较好，小任务权重高于学校层级。
- 如果候选人地点不接受，再强的学历也不优先。

## 5. Boss 操作省 Token 规则

### 5.1 读取规则

- 每次进入 App 先读当前页面状态。
- 只读取当前候选人的可见聊天和简历，不扩大到全列表全文。
- 附件简历读完后立即写 5-8 行摘要。
- 对已经总结过的候选人，后续只读取最新 1-3 条消息。

### 5.2 回复规则

- 不每次重新写完整岗位介绍。
- 使用模板，只替换候选人变量。
- 一条消息只解决一个核心阻碍：地点、简历、小任务、面谈、薪资/食宿。
- 对刚发过长消息的人，下一条要更短。
- 涉及薪资时只说“面谈后结合职责、能力、小任务表现和本地市场确定”，不主动报具体数字，不承诺食宿补贴。

### 5.2.1 面试日历同步规则

- 凡是已经与候选人明确时间的线下面谈、线上初筛、复试，都必须同步到团队可见的紫色日历。
- 只要会议方式、地点或候选人状态还未完全确认，日历标题或备注中要标注“待确认”。
- 日历事件至少包含：候选人姓名、岗位、面试形式、时间、地点/会议方式、BOSS 当前状态、需重点追问的问题。
- 候选人改期、取消、明确不匹配后，要同步修改或取消日历事件。
- 不把普通待回复、待做任务的人放入日历，避免污染团队排期。

### 5.3 批量推荐规则

推荐页候选人先按四项粗筛：

- 地点距离和迁移成本。
- 法律/文字/行政/内容相关经历。
- 期望薪资是否明显偏离。
- 是否有小任务可验证的潜力。

只对明显有潜力的人点“打招呼/继续沟通”。

## 6. 学校层级的内部使用方法

学校层级可以帮助估算培养成本，但不能直接表达给候选人。

内部判断顺序：

1. 地点和稳定性。
2. 小任务表现。
3. 文字表达和沟通反馈。
4. 实习/项目经历。
5. 学校、专业、成绩、证书。

原因：

- 对这个岗位，候选人的实际可塑性比学校名气更重要。
- 学校只能提示基础训练环境，不能替代任务表现。
- 对外提学校优劣会显得歧视，且容易损害雇主形象。

## 7. 可复用话术压缩模板

### 7.0 核心吸引力短版

```text
我们不靠“小县城”这个标签吸引人，真正的优势是低生活成本下的高密度成长。

团队成员有复合型法律背景和多年执业经验，律所在 AI 办公、法律检索、文书生产、案件管理和新媒体设备上投入很重：会用 Codex、Claude Code、ima 等工具，办公设备也不是普通文员配置。新人如果学习速度快，可以接触到比一般律所零散打杂更系统的训练。

所以我更看重你的可塑性、文字整理、执行力和能否校验 AI 输出，而不是只看你现在是不是已经成熟。
```

### 7.0.1 法律助理吸引力

```text
这个岗位不是传统行政文员，也不是让新人一上来独立办案。我们会重点训练事实整理、证据归类、法律检索、文书初稿、案件进度管理和 AI 协作办案。

团队里有复合型法律背景和五年以上执业经验成员，包括知识产权、合规、仲裁、专利代理、证券基金期货、会计等方向。对新人来说，价值不只是“有个工作”，而是能在真实案件里学会怎么把事实、证据、法律检索和文书串起来。

如果你愿意用一段时间集中训练，而不是在大城市只做很碎的螺丝钉工作，这里反而可能更适合成长。
```

### 7.0.2 实习生吸引力

```text
低年级或应届生没有经验不是硬伤。我们更看重学习速度、文字细致程度、执行稳定性和能否把 AI 输出改成自己理解、能落地的版本。

实习不是单纯复印、打杂、跑腿，会接触卷宗整理、法律检索、文书校对、案件流程观察、AI 协作办案和材料归档。只要时间能连续投入，成长密度会比普通短期实习高。
```

### 7.0.3 新媒体岗位吸引力

```text
我们正在以律师业务为切入口做法律新媒体，不是单纯拍摄剪辑，也不是只负责发视频。核心是把真实法律问题、案件经验、本地客户需求转成普通人看得懂、愿意咨询的短视频和图文。

设备方面有专业的拍摄、收音、灯光和办公设备，也有技术人员解决 AI 配置和设备问题。适合有内容能力、有想法、愿意从 1 到 100 一起开拓的人。
```

### 7.0.4 作息福利吸引力

```text
作息上我们是双休、7 小时工作制。长期看，单休和双休的差距非常大，不只是少休一天，而是多年下来生活质量和学习恢复时间都不一样。

办公环境也在持续完善，配套设施齐全。我们希望新人不是靠硬熬，而是在稳定节奏里持续学习和产出。
```

### 7.0.5 官方内容入口

```text
你也可以先关注我们的团队公众号，里面有一些日常工作动态和之前实习生的实习经历。团队抖音号也有一些短视频内容，在陆续更新。
```

### 7.0.6 远距离/大城市对比

```text
不要只看城市大小。大城市平台听起来更好，但新人也容易只做很碎的流程工作；本地的优势是生活成本、通勤成本低，同时能直接接触真实案件、AI 工具和系统训练。

律所在县城法院附近，有公交直达，附近租房成本相对可控。到高铁站交通也方便，和周边城市之间的流动成本没有想象中高。
```

### 7.1 地点顾虑

```text
理解，地点是现实因素。但也可以反过来看：本地租房、吃饭和通勤成本相对低，如果长期发展，实际压力未必比市区或大城市高。

我们真正的吸引力不是地点，而是团队带教、真实案件、AI 工具链和设备投入。这个岗位不是普通文员，重点训练 AI 协作办案、法律检索、文书初稿、案件材料整理和案件进度管理。如果你愿意先判断是否值得投入，可以先做一个 10-20 分钟小任务，再决定是否面谈。
```

### 7.2 食宿顾虑

```text
食宿和薪资结构需要面谈后明确，我现在不先承诺包吃住。可以确定的是，律所在法院附近，周边吃饭、租房和通勤配套比较方便。

如果后续确定长期做，住到附近通常比每天往返更省时间精力。面谈时可以把住宿成本、通勤方式、工资结构一起算清楚，再由你判断是否值得继续。
```

### 7.2.1 薪资边界

```text
薪资需要结合岗位职责、能力、小任务表现和面谈情况确定，我现在不能提前承诺具体数字。

这个岗位前期不是独立执业律师，也不涉及业务接洽、销售谈单、独立出庭或看守所会见。我们会按普通助理/培养型岗位的实际职责沟通，同时把本地生活、租房和通勤成本一起算清楚。
```

### 7.2.2 薪资 + 异地租房

```text
薪资边界我先说清楚：这个岗位前期是培养型律师助理，不是授薪律师，也不是业务销售岗，所以我现在不能按成熟律师助理/授薪律师口径提前承诺具体数字。具体会结合小任务、线上沟通、面谈和试用期实际职责来谈。

租房方面，本地整体租房、通勤和生活成本会明显低于南昌、长沙这类城市，但具体价格要看位置、新旧、家电和是否整租。后续如果双方都觉得匹配，来本地前可以把房租、通勤和薪资结构一起核算清楚。
```

### 7.3 小任务邀请

```text
你可以先做一个 10-20 分钟小任务，可以用 AI 辅助，但要自己整理结构和判断。我主要看事实整理、证据意识、检索方向和能否校验 AI 输出。双方都觉得匹配后，再安排面谈。
```

### 7.4 线上初筛确认

```text
可以先按这个时间预留一次线上初筛。我这边确认会议方式后再发你。

初筛主要聊三块：你过往实习或项目中具体做过哪些材料整理和文书工作；你对岗位长期方向的判断；以及薪资、通勤/租房、试用期职责这些现实问题。

这一步只是初步沟通，不等于直接录用或确定薪资。我们会结合简历、小任务、线上沟通和后续面谈综合判断。
```

## 8. 什么时候创建 Skill

当一个流程会重复使用 5 次以上，就适合做 Skill。

当前适合创建的 Skill：

- `boss-recruiting`：Boss 直聘招聘流程、筛选规则、话术模板、候选人摘要格式。
- `legal-assistant-screening`：律师助理/实习生的小任务评估标准。
- `new-media-screening`：律所新媒体岗位作品和转化能力评估。
- `interview-screening`：结构化面试、学习敏捷微测、反馈接受度、责任心和协作边界评分。

创建 Skill 的价值：

- 每次只加载流程入口，不重复加载全部背景。
- 模板、评分标准、停止规则稳定复用。
- 长资料放 `references/`，需要时再读取。

参考方向：

- OpenAI 的 skills 仓库提供了 Codex skills 的目录化范式：https://github.com/openai/skills
- Codex 示例强调脚本/模板可以减少反复写入上下文：https://github.com/openai/codex/blob/main/codex-rs/skills/src/assets/samples/skill-creator/SKILL.md
- 公开案例也常用“主 SKILL.md + 按需 references”的 progressive disclosure 结构，减少初始上下文：https://github.com/Gitmaxd/deepagents-cli-codex-skill
- 长任务 token 控制还可以参考 prompt caching 的思路：稳定内容放前面，动态工具结果和最新消息放后面，避免每轮重复塞入大量变化文本：https://arxiv.org/abs/2601.06007

## 9. 下一步建议

短期：

- 先用本 playbook 继续招聘。
- 每批简历处理后追加候选人摘要。
- 每天结束追加“今天有效话术/无效话术/待跟进名单”。

中期：

- 创建 `boss-recruiting` Skill，把固定流程和模板固化。
- 把候选人摘要表独立成单独文件。
- 把小任务评分标准独立成单独文件。
- 面试前读取面试筛选量表，按统一量表评分，避免只凭感觉判断候选人性格。
